Run 2 · 2026-09-12 · measuring the six fixes

Herdr vs herdr-axi

The same three tests, rerun the same day against the six changes run 1 produced. Two were CLI code, four were skill documentation. This run measures whether they worked, under a tightened benchmark harness that removes the scheduling artifacts run 1 was carrying.

Read Test → herdr-axi Synthesizer Test → herdr-axi Router Test → herdr-axi Tokens → herdr 2/3
The structural fixes worked The Read Test's spawn phase fell from 241.5s to 20.6s once the skill documented --no-wait as a pattern rather than as a flag. dispatch-workspace is now atomic: the workspace that ended run 1 with an orphan pane ended this run with exactly the two panes it was asked for, and no orphans appeared anywhere across six runs. Neither candidate fell back outside its assigned skill in any test, for the second run running.
But the wrapper lost tokens on the two spawning tests herdr-axi used 55% more tokens than raw herdr on the Read Test and 24% more on the Synthesizer Test, having won all three on tokens in run 1. The cause is not the speed it bought. It is a race in the settle loop the new guidance told candidates to hand-write, examined below.
What changed in the harness Run 1 gave both candidates the same pane names, so the one that ran second collided on Herdr's global agent-name namespace and lost most of its spawn phase to recovery — a penalty belonging to the schedule, not the skill. Every candidate now gets its own names. The Router Test fixtures are grounded in a brief file on disk rather than a conversational primer, which a fixture agent had refused as a prompt-injection attempt. Both changes are recorded in the benchmark prompt as numbered noise controls.

The spawn fix landed cleanly

The candidate read the new fan-out guidance and used it exactly as written — both dispatches non-blocking, settled afterwards rather than one at a time:

Spawn phase, run 2 
12.7  +5.7s  herdr-axi dispatch-workspace explorer_x1 ... --no-wait --prompt ...
21.1  +5.7s  herdr-axi dispatch explorer_x2 --workspace w26 ... --no-wait --prompt ...
28.9         mark spawned
Run 1's equivalent phase took 241.5 seconds, because every dispatch blocked on its own settle and one of them collided on a taken agent name.
And then the settle loop raced The candidate wrote the two-stage-free predicate the skill implied, and it returned in 1.4 seconds instead of running for minutes: 
until herdr-axi | grep -q 'explorer_x1.*idle\|explorer_x1.*done'; do sleep 5; done
--no-wait returns before the agent has begun, so the first poll saw idle — the state an agent occupies before it starts as well as after it finishes — and the loop exited immediately. With its wait gone, the candidate killed time with six no-op shell calls, each one a full model turn resending the whole context.

A different cause, same shape

This candidate did not use --no-wait at all — three plain blocking dispatches. Its 6 extra turns come from a redundant fourth read: read synth_x --full returned a body that began mid-sentence, and read synth_x --lines 240 was needed to recover the opening.

--full lifts the 1500-character cap. --lines widens the scrollback window. They are independent, and the rewritten read section described both correctly without ever saying they were separate, so the candidate read --full as "give me everything".

The raw-herdr candidate's 13 calls include three pure discovery calls — herdr --help, herdr workspace, herdr agent — which its own skill still invites before the first real command.

The control case

No polling, no --full reads, and the wrapper wins tokens by 30% — exactly as it did in every test of run 1. This is the cleanest evidence that the regression above is not a property of the wrapper but of what the new guidance made candidates do while waiting.

The herdr-axi candidate did capture only the engineer's headline sentence and drop the architecture behind it. That is a candidate miss, not a tool defect: the plain read reported size: 3266 and help[1] named --full, and --full returns the complete answer. It simply did not follow the line it was given.

Why the tokens moved

Tokens here are not bytes read. They are model turns, because every turn resends the whole conversation as cache-read context.

Per-turn cost is identical to within 3%. The gap is 15 extra turns at ~68.5k each, about 1.03M against an actual gap of 1.09M. The whole regression is turn count. Nothing about the reads got bigger.

So was speed bought with tokens?

Mostly no. A blocking wait costs zero model turns while it waits — one call sits there for four minutes and the model is never invoked. Polling always returns control at least once, so it has a floor the blocking path does not. But that floor is one blocking until-loop plus one confirmation read: about 2 turns, not 15.

The other 13 were the candidate improvising after its wait exited early. Had the loop held, the wrapper would have landed near parity on tokens while still finishing 27% faster.

What this run earned

Three further changes, all in the skill, all narrower than run 1's six.

  1. Stage the settle predicate. Watch for working first, then for the settle. A status of idle before work begins is indistinguishable from idle after it ends, and the blocking path's built-in lifecycle guard is exactly what --no-wait removes.
  2. Block in one call while waiting. State that a blocking wait costs no turns and every return to the agent loop costs one, so a settle happens inside a single call and never as no-op commands between checks.
  3. Say that --full and --lines are independent caps. One lifts the character limit, the other widens the scrollback window, and clearing one leaves the other in place.

The deeper answer

All three describe an agent hand-writing a wait loop in shell and getting it subtly wrong. Two independent candidates produced the same buggy loop from the same guidance, which argues the gap is in the wrapper rather than in its documentation — a settle command that takes a list of agents and blocks correctly would remove the hazard instead of teaching every caller to avoid it.

Overall

The fixes worked on everything they were aimed at. herdr-axi went from winning one test on time to winning all three, its spawn phase fell by an order of magnitude, and the orphan workspace is gone. What run 1 identified as a structural capability gap is closed, and for the second run running neither candidate needed to leave its assigned skill.

The token regression is real but narrow, and it is not the price of the speed. It is a race in a shell loop the new guidance invited candidates to write by hand, plus a pair of independent length caps that read like one. Both are documentation-shaped problems sitting on top of code that behaved correctly throughout.
