Herdr vs herdr-axi

Two identical candidate agents per test, one driving Herdr through the raw /herdr skill, the other through the /herdr-axi CLI wrapper. Same prompt, same model, same effort. Each candidate now works inside its own named workspace (TEST-<test> / TEST-<test>-axi) with all its subagents as panes inside it, and the Router Test runs its two candidates sequentially against one shared workspace instead of in parallel.

Read Test → herdr Synthesizer Test → herdr Router Test → herdr (narrow)
Why this is a rerun The first run tested herdr-axi against an unmerged worktree branch with a follow-up commit made mid-session — not a settled artifact, and not the same footing herdr was tested on. That branch is now merged to master (commit 20c6e4f) and the skill's symlink repointed at the merged copy. This report reflects the rerun only; the first run's numbers are superseded.

What happened

herdr-axi spawned its first pane much faster (5.4s vs 24.1s), but that lead evaporated: its dispatch-workspace call can only create one agent, and adding the second pane into that same workspace, plus prompting it, is outside what dispatch/dispatch-workspace cover — the candidate had to fall back to five raw herdr calls to finish the setup. herdr needed zero fallbacks. Both candidates got matching, non-contradictory findings on the holiday-calendar mechanism.

Cleanup

Both candidates genuinely left their workspace open. A follow-up verification agent confirmed each was still live, then closed it — the intended cleanup step, not the candidate closing its own work early.

Note herdr's own friction was a harness-level Bash timeout misreporting a backgrounded agent prompt --wait call as failed — the underlying agent had actually finished, confirmed by polling agent get. Not a herdr defect.

What happened

Both synthesized reports independently landed on the same read of batch-fleet and skill-authoring — thin-launcher-plus-guide structure, append-only learnings loops, verification over self-report. The gap is again structural, not incidental: herdr-axi's dispatch-workspace names the workspace after the agent (must be lowercase, so it can't produce an exact mixed-case label like "TEST-synth-axi" directly) and cannot add a 2nd or 3rd pane to a workspace it already created — over half the setup had to go through raw herdr calls. herdr needed no fallback at all and finished in under half herdr-axi's time.

Issue — herdr-axi Two requested agent names collided with pre-existing live agents elsewhere in the session and needed an -axi suffix. One analyst pane hit the alternate-screen read limitation and needed a file-based workaround (handled internally by the synthesizer). Neither issue changed the outcome, but both added to the fallback burden already forced by the missing "add to existing workspace" primitive.

With the shared-resource contamination removed (sequential execution, one pre-built workspace), the gap nearly disappears: herdr finishes in 20.2s vs herdr-axi's 20.9s, a 4% difference. Both candidates needed the exact same raw-herdr fallback for the exact same reason — neither skill's dispatch commands can prompt an agent that already exists, only create new ones. That's a shared capability gap in both tools, not a differentiator. herdr's edge here is a small, real margin, not the wide gap seen in the first run, which was more about workspace/pane-collision noise than the router logic itself.

Overall

herdr won all 3 tests, but the margin varies with what's actually being measured. On the Read and Synthesizer tests — where a candidate must place several agents inside one workspace it created — herdr-axi's dispatch/dispatch-workspace repeatedly can't add a 2nd or 3rd agent to an existing workspace, forcing raw-herdr fallbacks for most of the setup and losing 1.8x–4x on time. On the Router Test, where the task is locating and messaging an already-existing agent, both skills hit the identical gap (no "prompt an existing agent" primitive) and the result is a coin-flip-sized 4% margin. The real finding isn't "herdr is faster" — it's that herdr-axi's wrapper covers the create-one-new-agent case well, but degrades to raw herdr for anything beyond that.

Metrics worth adding

  1. Fallback-call count. Now tracked qualitatively per test (0 for herdr throughout; 3–5 raw-herdr calls for herdr-axi on Read/Synth, 1 shared call on Router). Worth promoting to a first-class number — it explains the timing gap better than tool-call totals do, since a fallback call and a native one aren't equally expensive.
  2. Structural capability gaps vs incidental friction. This rerun separates two different failure modes that were blended before: herdr-axi's inability to add a pane to an existing workspace is a structural gap (present every time, same root cause); a frozen alt-screen pane or a stale name collision is incidental noise (situational, not guaranteed to recur). Scoring them the same understates how load-bearing the structural gaps are.
  3. Answer fidelity, not just presence. The Router Test judges correctness as "reached x_engineer, got a technical answer" — worth also scoring whether the wording stayed close to the seeded framing versus drifting, since that's a signal of whether routed context survived intact.
  4. Real token cost. Candidates still could not self-report token usage in this rerun — neither harness exposes a /cost-equivalent inside a subagent context. The numbers here come from the workflow's own per-agent tracking, not the candidates.
