Herdr vs herdr-axi

Two candidate agents per test, one driving Herdr through the raw /herdr skill, the other through the /herdr-axi CLI wrapper. Same prompt, same model, same effort, run strictly sequentially. Each candidate is a real Claude Code session in its own pane, timing itself with timestamps written outside its own context, with token usage read back from its own transcript.

Read Test → herdr-axi Synthesizer Test → herdr Router Test → herdr Tokens & calls → herdr-axi 3/3
What changed since the 2026-09-11 run That run's headline finding was that herdr-axi could not add a second or third agent to a workspace it had already created, forcing raw-herdr fallbacks through most of every setup. dispatch --workspace now exists. Across all six runs today, neither candidate fell back outside its assigned skill even once. The comparison below is the first one measuring the two wrappers on equal footing.
Do not compare these token numbers to the 2026-09-11 report That run reported roughly 50k per candidate from a workflow's per-agent tracking. This run sums input, output, cache_creation and cache_read from each candidate's own Claude Code transcript, which is why the totals are in the millions. Cache reads dominate that figure and move with context size, so the output-token subtotal is reported alongside it. Both candidates in a test are measured the same way, so the within-test comparison holds; the across-run comparison does not.

Why spawn and read are not comparable line by line dispatch bundles split, start, prompt and settle-wait into one call, so a sub-agent's entire first turn lands in the herdr-axi candidate's spawn phase. The raw-herdr candidate splits and starts first, then prompts, so the same work lands in its read phase. The two phases swap places; only the total is comparable. This holds for all three tests.

What happened

The herdr-axi candidate finished 157 seconds ahead on a task where both explorers did identical research, and used 41% fewer tokens doing it. Both landed on the same answer: the concept is contained entirely in the internal domain, split into TenantHolidayCalendar and PublicHoliday, with the same models, usecases, apiv2 surface, migrations and tests named by both explorers in both runs.

The raw-herdr candidate lost most of its margin to a harness boundary rather than to Herdr: two of its calls were killed at 120 seconds by the Claude Code Bash tool and backgrounded, costing 241.9 seconds of its 401.8 second read phase. See the tooling findings below.

Issue — herdr-axi dispatch-workspace explorer1 failed with agent_name_taken because the other candidate's still-open panes held that name — Herdr agent names are one global namespace, not scoped per workspace. The failed call had already created workspace w1S and an empty root pane before the name check ran, leaving an orphan behind. The candidate recovered by suffixing both names and adding them with dispatch --workspace, and still won the test.

What happened

Both synthesizers were correctly denied the source files and read the analyst panes through Herdr, and both landed on the same reading of the two documents: a thin-launcher skill whose procedure is deferred into a guide, and the guide that mandates exactly that shape.

The 28-second gap is entirely the settle-wait. The herdr-axi candidate's three dispatch calls blocked for 21.9s, 21.9s and 49.2s — 93.0 seconds of its 105.5 second spawn phase, or 88%. It issued them in three separate turns, paying another 8 seconds of model gap, when the second and third share no state and could have gone out together. The raw-herdr candidate issued its three agent start calls in one batch and prompted afterwards.

Issue — herdr-axi --no-wait exists and neither herdr-axi candidate used it in any test. The skill lists the flag but never says when to reach for it, and nothing tells an agent that independent dispatch --workspace calls can be batched. This one documentation gap accounts for most of the loss in this test.

What happened

Both candidates returned the engineer's architecture answer verbatim and neither touched the product manager. The herdr-axi candidate found the workspace and both panes in one bare herdr-axi call where the raw-herdr candidate needed workspace list plus agent list — and still lost, because it then spent two reads where one would do, and wrote its own timing marks out of order.

On a task this short the floor dominates: of the 28.7 seconds the raw-herdr candidate took, roughly 20.5 seconds was the model's thinking gap between calls and only about 11.8 seconds was time inside herdr. At low effort every tool call costs around 1.5 seconds of Bash round trip plus 2.2 seconds of model gap before the command does anything at all.

Issue — herdr-axi read returned the answer truncated mid-word and flagged the pane as frozen on an alternate-screen frame, so the candidate re-ran with --full: 11.2 seconds for what should have been 5.6. In the Synthesizer Test the identical warning fired on two panes whose bodies were already complete. The same signal fires whether content is missing or not, so an agent that trusts it wastes a read now and an agent that ignores it wastes a read later. Today's candidates did one of each.

Overall

herdr-axi wins on cost, herdr wins on latency for small jobs. herdr-axi used 26% fewer tokens and 35% fewer calls, and won every single test on both. It won wall clock only on the Read Test, where the work was long enough to absorb the settle-wait that dispatch forces; on the two short tests the raw-herdr candidate was faster precisely because it can start an agent and prompt it as separate steps.

That framing matters more than the scoreline: the wrapper's remaining time losses are not structural any more. Every one of them traces to a documented flag the candidates did not know to use, or to a signal the CLI reports ambiguously. The capability gap that decided the 2026-09-11 run is closed, and neither candidate needed a fallback in any test.

Metrics added to the benchmark

All four are now written into docs/codebase-benchmark.prompt.md with their measurement method, so two runs produce comparable numbers.

  1. Calls to task. Herdr control commands between the first control call and the last read, excluding instrumentation. This is the metric the wrapper is designed to move, and it is far less noisy than wall clock — at low effort a call costs ~3.7s of floor regardless of what it does. herdr-axi won it 3/3 even in the tests it lost on time.
  2. Recovery cost. Seconds and calls spent recovering from an error, reported separately with the triggering error named. Without it, the Read Test's name collision hides inside a normal-looking 241.5s spawn number.
  3. Instruction-fidelity defects. A counted list, not a yes/no, verified against a live home view rather than the candidate's own claim. This run: herdr 0, herdr-axi 2 — one orphaned pane, one set of timing marks written out of order.
  4. Total task time as the primary figure. Measured from first action to last read, stopping before the candidate composes its report file, which cost 16–19 seconds of pure instrumentation in every run.

Six candidate runs, each a real Claude Code session on Sonnet 5 at low effort in its own Herdr workspace with its own empty working directory, executed strictly sequentially. Timing comes from five fixed marks each candidate wrote to a file outside its own context; token usage is summed from each candidate's own transcript, filtered to that candidate's session and cut at its final mark. Pre-flight confirmed both skills on master with clean trees, the herdr-axi CLI repo on master with all feature branches merged, and herdr-axi doctor reporting status: match against herdr 0.8.0.

The Router Test was run twice. The first attempt was discarded because the fixture agent refused a roleplay primer as a prompt-injection attempt; the fixture was rebuilt to read a real brief file from disk, and both candidates ran against the rebuilt version. All eleven workspaces created for this benchmark were closed afterwards and the session verified back at its original six.
