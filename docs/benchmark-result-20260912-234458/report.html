The settle command

Run 2's guidance told candidates to settle a --no-wait dispatch by writing a shell poll over the home view. Two independent candidates wrote the same broken loop, which is the signature of a missing primitive rather than missing prose. It is now one command.

Interface 
herdr-axi settle <name>... [--all] [--timeout <ms>]
exit: 0 all settled, 1 one or more still open at the deadline, 2 usage error.

Why a status poll cannot be made correct

A freshly dispatched agent reports idle before it starts working, which is the same status it reports after it finishes. A single snapshot cannot tell those apart, so run 2's one-stage loop exited 1.4 seconds after dispatch. Staging it — wait for working, then wait for the settle — fixes that case and introduces a worse one: a task that starts and finishes between two polls is never observed working, and the first stage waits forever on a job already done.

settle does not poll status. It tracks Herdr's per-agent state-change sequence number and runs a two-state machine. An agent whose baseline is already working is active: the next settled status is unambiguously real. An agent whose baseline is anything else is unconfirmed, and only a movement in the sequence number proves a transition happened. The sequence moves even when the working moment itself is never sampled, so the fast cycle that hangs the staged shell loop resolves correctly here.

Bounded by construction

The skill already capped blocking calls at roughly 90 seconds, because the harness running these agents kills a longer foreground command and loses its return value. An unbounded settle loop contradicted that cap. settle defaults to a 60-second deadline, and a name still open at the deadline is a normal result — exit 1, naming the agents still running — so the caller simply calls it again. The timeout now lives inside the tool instead of in prose a reader has to reconcile.

The poll interval is 2000ms, chosen as roughly a fourfold margin over a live measurement of the race window at 0.523s, recorded in the repository's own baseline fixtures rather than guessed.

Verified against the exact race that broke run 2 
dispatch returned after 4.2s
herdr-axi settle settletest
  settletest,done,null
counts: 1 of 1 settled
settle blocked for 6.1s
The agent counted to 40 and replied DONE; settle returned only after that. No early return on the not-yet-started idle. The task was short enough to also exercise the fast start-and-finish cycle that hangs the staged shell loop.
And the partial-settle path exercised itself in the benchmark From the Read Test candidate's own friction report: the first settle explorer_x1 explorer_x2 --timeout 90000 returned exit 1 with neither agent settled, it re-ran the same command once, and both came back done. Bounded wait, honest partial result, trivially resumable — read correctly by a candidate working only from the skill text.

Over the same three runs the wrapper went 4.07M, then 6.49M, then 3.66M: up 59%, then down 44%.

A control that steady is what makes the wrapper's swings readable as signal. Run 2's regression was real and run 3's recovery is real, and neither is the day, the machine, or the model having an off afternoon.

Overall

Three runs, nine changes, and the wrapper now wins every measure it is asked about. The path there is worth more than the scoreline: run 1 found a capability gap, run 2 found that closing it in documentation moved the cost rather than removing it, and run 3 found that moving the same logic into a command removed it properly.

Each round's regression was narrower than the last, and each was caught by measurement rather than by review. The one finding still fully open belongs to neither wrapper: a blocking call longer than the harness's foreground limit is killed and loses its return value, and the raw-herdr candidate lost a call to it again in the Read Test. That skill is the benchmark's control, so it stays as it is.

Six candidate runs, each a real Claude Code session on Sonnet 5 at low effort in its own Herdr workspace with its own empty working directory, executed strictly sequentially. Timing comes from five fixed marks each candidate wrote to a file outside its own context; token usage is summed from each candidate's own transcript, filtered to that candidate's session and cut at its final mark. Calls to task are counted from the transcripts, not from the candidates' self-reports. The herdr-axi test suite stands at 160 passing, up from 136 before this round of work.

Pre-flight confirmed both skills on master with clean trees, the herdr-axi CLI repo on master with every fix branch merged, the global binary symlinked into that repo so the fixes were live, and herdr-axi doctor reporting status: match against herdr 0.8.0. All eleven workspaces created for this run were closed afterwards and the session verified back at its original six.

Two caveats. Both wrapper candidates passed --timeout 90000 rather than relying on the 60-second default, so the default's headroom argument is untested here. And the 2000ms poll margin rests on a single live measurement of the race window; a slower machine could push agent pickup past it, at which point settle would wrongly trust its baseline.
